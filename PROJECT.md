# Находка — главная идея проекта

Нужно получить небольшой сайт для возвращения потерянных вещей владельцам. Пользователь регистрируется, входит в аккаунт и публикует объявление «Потерял» или «Нашёл». В объявлении есть название, описание, категория, город, место и дата события.

Общая доска доступна всем. На ней можно искать объявления по словам и выбирать город, категорию и тип. На странице объявления зарегистрированный пользователь оставляет текстовый отклик. Автор объявления может изменить публикацию, удалить её или отметить, что вещь нашлась либо возвращена владельцу. Закрытая публикация остаётся в истории автора, но новые отклики под ней не принимаются.

Например, Анна нашла ключи в парке и создала объявление. Дима увидел его, описал свой брелок в отклике и договорился с Анной о возврате. После возврата Анна закрыла объявление.

В готовом приложении объявления, пользователи и отклики сохраняются в PostgreSQL и не исчезают после перезапуска. Каждый пользователь управляет только своими объявлениями. Чужую публикацию нельзя изменить даже прямым запросом к API.

## Стек

| Технология | Для чего она нужна здесь |
| --- | --- |
| Python 3.12+ и FastAPI | HTTP API приложения |
| Pydantic 2 | Проверка входных данных и формат ответов |
| PostgreSQL | Пользователи, объявления и отклики |
| SQLAlchemy 2 Async и asyncpg | Модели, связи и асинхронные запросы |
| Alembic | Миграции таблиц |
| PyJWT | JWT-токен доступа с ограниченным сроком действия |
| pwdlib с Argon2 | Хеширование и проверка паролей |
| pydantic-settings | Настройки из переменных окружения |
| Docker Compose | Среда с PostgreSQL и фронтендом |
| Git | История изменений проекта |
| Pytest и HTTPX | Проверка входа, операций с объявлениями и прав доступа |
| HTML, CSS и JavaScript | Готовый интерфейс в `dist/` |

Всего три сущности: `User`, `Notice`, `Reply`. Одному пользователю принадлежат несколько объявлений и откликов; одному объявлению принадлежат несколько откликов. При удалении объявления удаляются и его отклики.

Для авторизации используются один JWT-токен доступа и повторный вход после истечения его срока. Подход с PyJWT и pwdlib описан в [официальном руководстве FastAPI](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/).

## Контракт готового фронтенда

Это описание входов и выходов для подключения интерфейса, без расписания разработки.

| Метод и путь | Данные или результат |
| --- | --- |
| `POST /auth/register` | JSON: `name`, `email`, `password`; ответ — пользователь |
| `POST /auth/login` | JSON: `email`, `password`; ответ: `access_token`, `token_type: "bearer"` |
| `GET /auth/me` | Текущий пользователь: `id`, `name`, `email` |
| `GET /notices` | Массив объявлений, включая закрытые; фронтенд фильтрует доску |
| `GET /notices/{id}` | Полное объявление с массивом `replies` |
| `POST /notices` | Созданное объявление; автор берётся из токена |
| `PATCH /notices/{id}` | Изменённое объявление; доступ только автору |
| `DELETE /notices/{id}` | `204 No Content`; доступ только автору |
| `POST /notices/{id}/replies` | JSON: `text`; ответ — новый отклик |

Создание объявления принимает `title`, `description`, `kind`, `category`, `city`, `place`, `event_date`. Значения `kind`: `lost`, `found`; `category`: `keys`, `headphones`, `backpack`, `other`. Для изменения также доступно поле `status`: `open`, `resolved`.

Объявление в ответе содержит эти поля, а также `id`, `created_at` и `owner: {id, name}`. Полный ответ содержит `replies`: каждый отклик имеет `id`, `text`, `created_at`, `author: {id, name}`. Дата события — `YYYY-MM-DD`, дата публикации — ISO 8601. Для учебной версии `image` может быть пустым; загрузка фотографий не требуется для основного сценария.

Защищённые запросы получают `Authorization: Bearer <access_token>`. Ошибки с понятным текстом возвращаются как `{"detail": "Сообщение"}`. Выход в интерфейсе удаляет токен из памяти страницы.
